## Global consistency pass

After corrections A–G, the full design was re-checked: all five schemas (`admin`, `audit`, `security`, `preview`, `ops`); every table's PK/FK/`ON DELETE`/unique/index set (including the new `admin.identity_operations` and `audit.audit_chain_head`); RLS policies and the §10 matrix (now consistent with §20.6 views and §20.11 predicate); view security models (each client-accessible view has one); SECURITY DEFINER functions (§8.4 lockdown, now including the unified predicate); service-role permissions (§20.2 unchanged and consistent); the ERD (chain-head relationship added); the audit hash-chain (§20.4 complete field coverage); the migration sequence (§13 single-transaction rule, chain-head seeding); the RBAC catalogue (30 assignable + 1 non-assignable, unchanged); and the MFA/session flows (§§20.3, 20.5, 20.7, 20.11 mutually consistent). Phase 7.1 and Phase 7.3 requirements are preserved — Phase 7.4 removes or rewrites the contradictory text they had left behind. The four open Phase 6 items (Site URL/redirect allowlist, password-policy strengthening, AAL2 enforcement *implementation*, first Super Admin creation) remain open by design and are unaffected.
