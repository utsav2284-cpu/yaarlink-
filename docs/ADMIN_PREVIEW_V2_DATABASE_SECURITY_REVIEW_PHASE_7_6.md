## Final regression report

- **Platform facts actually verified:** Phase 6 Auth configuration state (public signup disabled; TOTP enroll/verify enabled; passkeys disabled); Supabase JWT `aal`/`amr` semantics — `aal2` alone does not prove TOTP, the `amr` `totp` timestamp evidences last verification (official Supabase JWT-fields documentation); documented sign-out scopes revoking refresh tokens while issued access tokens remain valid until `exp`, and the absence of a documented per-session-ID Admin deletion API (official sign-out documentation); PostgreSQL 15+ `security_invoker` views, supported on this project's PostgreSQL 17; PostgreSQL CHECK constraints cannot validate other tables (deferred constraint triggers used instead); the §20.4 audit test-vector hash was genuinely computed from the defined formula during this review.
- **Decisions specified in writing only:** the complete database schema and all constraints, policies, views, functions, triggers, the bootstrap predicate, the identity-operation saga, the audit hash chain, and every Phase 7.1–7.6 correction.
- **Features not implemented:** every item above — no table, policy, function, registry, chain, enforcement, or bootstrap exists in the Preview project.
- **Tests still requiring future runtime execution:** all cases in §§14/20.9 (28 cases, now including bootstrap-without-profile/registry, revocation taxonomy, the audit test vector, and the migration-sequence replay). No test has been run or passed, and none is claimed.

## Complete list of unresolved issues

1. Supabase Site URL + redirect allowlist not configured (blocks invitations and invite-flow testing).
2. Password policy still needs strengthening (≥12 characters, character rules, leaked-password/HIBP check).
3. Mandatory AAL2/TOTP enforcement (§20.11 predicate) is designed, not implemented.
4. No first Super Admin account has been created; the operator bootstrap procedure is unrehearsed.
5. Admin JWT lifetime shortening (3600s → e.g. 900s) remains a Phase 8/9 decision.
6. Auth refresh-token cleanup for another administrator may remain *pending/unavailable* where Supabase offers no supported mechanism; database enforcement does not depend on it.
7. Incapacitated-owner recovery and operator bootstrap are procedural controls requiring a written, rehearsed runbook at implementation time.
8. Direct-API authorization *denials* are silent in the database; monitoring depends on Auth/PostgREST logs (Phase 9 tooling).
